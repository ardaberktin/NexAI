# Reporting security issues

Use **Security → Report a vulnerability** in the repository if private vulnerability reporting is enabled. If the option is unavailable, ask the maintainer for a private reporting channel and share a minimal, sanitized description there.

Include the affected version, component, relevant prerequisites, and the impact you observed. Keep pairing profiles, access tokens, OAuth credentials, voice data, personal recordings, and real archive contents out of reports.

The deployment guide assumes a private tailnet, device-specific credentials, and an SSH tunnel for the admin console. [Server setup](server/README.md)
